| Mo et al., KGGen: Extracting Knowledge Graphs from Plain Text with Language Models (read in detail), arXiv 2502.09956, https://arxiv.org/abs/2502.09956 | 2025 | Can LMs extract dense, high-quality KGs from plain text, given that existing extractors (OpenIE, GraphRAG) give sparse graphs with almost as many relation types as edges? | Single LLM in three stages (Sec. 4): (1) two-step extraction, entities then subject-predicate-object triples (Gemini 2.0 Flash via DSPy); (2) aggregation across sources, no LLM; (3) entity and edge resolution: S-BERT embeddings, k-means clusters of 128, top-16 candidates by BM25 plus embeddings, LLM de-duplication with a canonical alias | MINE-1 average 66.07% vs GraphRAG 47.80% and OpenIE 29.84% (Fig. 3, model for this number not stated in the figure); by model 73% Claude Sonnet 3.5, 66% GPT-4o, 44% Gemini 2.0 Flash (Table 1); MINE-2 80.63% vs GraphRAG 81.20%, comparable (Fig. 5); cost for 1M chars: 5.37M tokens, $0.84, of which resolution is 3.15M tokens (Table 3); GraphRAG token cost not reported (time only, Table 4); repeated runs not reported for MINE-1 | Staged single-LLM pipeline with explicit per-stage token cost; MINE is a candidate benchmark; no single-agent vs multi-agent comparison | Strengths: open code, reusable MINE benchmark, per-stage token and dollar cost reported (Table 3).
